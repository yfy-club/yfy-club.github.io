### 核心背景与技术定位

技术成长最怕的不是难度，而是失序：教程看了一轮，关掉视频却写不出十行能跑的代码；热门技术追了一圈，简历上却拼不出一条完整的能力线。根因在于把「看过」当成了「会了」，把「碎片」当成了「体系」。

社团的培养阶梯就是为解决这个问题而设计的：把大一到大三的成长拆成八个可验证的阶段，每个阶段都有明确的底层原理目标、可交付的大作业与强制的代码评审。成长不再是个人摸索，而是一条有检查点的工程化流水线。

#### 为什么必须按阶梯推进

底层决定上限。跳过指针与内存直接学框架，写出来的代码遇到性能问题就无从下手；跳过数据库原理直接调 ORM，慢查询只会盲目加索引。阶梯的每一层都为下一层提供「出问题时有能力向下追」的底气，这正是工程能力与调包能力的分界线。

#### 培养体系的演进脉络

社团培养从早期的「学长口头带教」演进为「任务书 + 大作业 + 代码评审」的三段式体系，再沉淀为本档案库的成文规范。每一次演进都源自真实的翻车复盘：评审缺位导致同类错误反复出现，于是有了审查清单；新人提问低效，于是有了第一周生存手册。这份蓝图本身就是工程沉淀机制的产物。

### 阶段阶梯全景

八个阶段自底向上排布，前一阶段的产出是后一阶段的入场券：

| 阶段 | 核心任务 | 能力目标 | 产出目标 |
|---|---|---|---|
| 编程通识 | 计算机科学启蒙 | 建立二进制、算法、内存与工程的全景视野 | 完成 CS50 全部实验并复盘笔记 |
| 阶段一 | C/C++ 语法启蒙 | 掌握指针、内存模型与基础数据结构 | 手写动态扩容顺序表与双向链表 |
| 阶段二 | Web 前端视野 | 掌握 HTML5、CSS 布局与 JS 异步交互 | 原生 JS 无障碍交互看板 |
| 阶段三 | JavaSE 企业级基础 | 掌握面向对象、集合底层与异常体系 | 单机综合信息管理系统 |
| 阶段四 | 系统与数据底座 | 掌握 Linux 运维与 MySQL 设计调优 | 多表关联业务库与执行计划报告 |
| 阶段五 | 企业级 Web 工程 | 掌握 Maven、MyBatis 与三层架构 | Spring Boot 脚手架与双 Token 认证 |
| 阶段六 | 真实工程与 AI 协作 | 参与生产级研发与学科竞赛 | 社团开源项目的合入特性 |
| 进阶阶段 | 高年级分流攻坚 | 微服务高并发或计算机 408 深造 | 就业项目集或考研真题体系 |

### 成长闭环与学习节奏

每个阶段内部走同一个三步闭环，任何一步缺失都算没有完成该阶段：

| 环节 | 做什么 | 通过的标志 |
|---|---|---|
| 概念认知与原理学习 | 读文档、看教程、推演底层机制 | 能不看资料向同伴讲清原理 |
| 大作业实战编码 | 独立完成阶段产出目标 | 功能完整且带防御性代码 |
| 骨干代码评审 | 提交代码接受审查与答辩 | 评审意见全部闭环销项 |

#### 三个年级的节奏分工

大一是筑基年：以阶段一到阶段四为主线，重点是底层原理与编码量，考核以基础功验收为准。大二是实战年：完成阶段五与阶段六，进入真实项目与竞赛，同时承担对大一的讲课答疑与带教，教是最好的学。大三是分流年：按就业或考研进入进阶阶段，同时作为架构骨干回带项目，完成从「被带教」到「带教者」的身份闭环。

#### 每周最小投入基线

实验室考勤要求常规周打卡满 22 小时，技术投入建议遵循「三二一」节奏：每周至少三次编码会话、两次原理复盘、一次向师傅或同伴的口头讲解。连续两周没有任何产出，应主动向师傅暴露进度而不是沉默拖延。

### 代码评审与导师沉淀机制

评审不是挑错表演，而是把个人错误转化为团队资产的机制。每个阶段的大作业完成后，必须预约师傅进行一对一代码审查与创新点答辩。

#### 评审的四个关注面

审查按四个维度逐项过：代码规范性（命名、结构、格式）、逻辑严密性（边界、分支、异常路径）、异常健壮性（空值、资源、并发安全）、模块解耦度（依赖方向、职责单一）。评审意见以清单形式给出，成员逐条销项后复审，未销项不得进入下一阶段。

#### 提交记录自查

评审前先自查最近的提交记录是否干净可回溯，这是工程素养的第一道门面：

```bash
# 查看最近五次提交的摘要与变更范围，确认每个提交只做一件事
git log --oneline --stat -5

# 提交前检查暂存内容，防止把调试代码与密钥文件带进历史
git diff --cached

# 提交为空或工作区不干净时先处理现场，再继续评审流程
git status
```

#### 沉淀的三个去向

评审中暴露的共性问题会沉淀到三个地方：高频错误写进《测试与评审规范》的审查清单，环境类问题写进《高频故障排查手册》，架构级结论写进对应阶段的路线篇目。你今天踩的坑，会成为下一届新人的路标。

### 路线执行与验收清单

各阶段验收均为可量化指标，不接受「我觉得我会了」式的自我认定：

| 阶段 | 验收清单 |
|---|---|
| 阶段一 | 顺序表与链表通过师傅的边界用例集；能口述栈堆差异与虚表寻址 |
| 阶段二 | 看板通过键盘导航与防抖搜索验收；能口述事件循环调度时序 |
| 阶段三 | 信息系统通过异常注入测试；能推导 HashMap 树化阈值的由来 |
| 阶段四 | 业务库通过外键与索引规范检查；能解读 EXPLAIN 各字段含义 |
| 阶段五 | 脚手架通过接口契约门禁；能解释事务失效的三种场景 |
| 阶段六 | 特性代码合入主干；能独立完成从需求分析到合并请求的全流程 |

启动任何阶段前，先通读对应篇目，再到师傅处确认任务书；完成验收后，在复盘会上用十分钟讲清「这个阶段我错得最惨的一次」——能讲清失败，才算真正完成。
