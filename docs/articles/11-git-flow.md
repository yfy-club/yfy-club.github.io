### Git 底层对象与状态流转模型

深入理解 Git 的底层存储机制：

```
Blob 对象   存储文件具体内容与哈希值
Tree 对象   记录目录树结构与文件名映射
Commit 对象 记录快照树指针、父提交引用、作者信息与提交说明
```

掌握代码在四大区域之间的流转：工作区（Working Directory）进行文件修改，通过 `git add` 收集至暂存区（Index），通过 `git commit` 生成本地提交历史，最终通过 `git push` 同步至远程共享仓库。

### 分支管理策略与命名规范

推荐的分支命名约定：

```
feat/<简短模块名>     新功能或特性开发
fix/<简短问题名>      缺陷与 Bug 修复
chore/<维护任务名>    依赖升级、构建配置调整
docs/<文档篇目名>     文档编写与更新
```

所有日常开发均应基于最新的主分支（`main`）检出特性分支进行，开发测试完成后通过发起合并请求（PR）并入主干，避免直接向主分支推送提交。

### 提交记录原子性与 Conventional Commits 规范

遵循小步多次提交原则，保证每个提交记录仅包含一个独立的逻辑变更。

提交信息推荐采用 Conventional Commits 规范，结构清晰表述变更意图：

```
feat(auth): 增加用户登录参数格式校验
fix(table): 修复移动端表格数据溢出遮挡
refactor(user): 抽取通用权限校验中间件
```

### 合并请求流程与敏感数据脱敏

发起合并请求时，说明文档建议包含三项核心内容：改动内容、改动原因、验证方式与测试结果。

涉及前端界面调整时建议附带操作录屏或前后对比截图；截图前需对真实姓名、学号、手机号及线上密钥等敏感数据进行严格脱敏处理。

团队共享仓库的主分支建议开启分支保护，禁用强制推送（`git push --force`），保障版本演进历史的完整可追溯。
