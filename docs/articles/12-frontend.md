### TypeScript 严格模式与类型约束

前端项目推荐开启严格类型检查（`strict: true` 与 `strictNullChecks: true`），充分发挥编译期类型系统的保护作用：

```ts
// 推荐使用可辨识联合类型进行状态建模
type RequestState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; error: Error }
```

避免滥用 `any` 或连续类型断言进行类型逃逸；对于可选字段，推荐显式声明 `undefined` 联合类型，确保类型契约严密。

### 目录结构与单一真源原则

项目文件组织遵循单一真源原则，按领域或功能职责明确划分：

```
src/
├── components/   通用组件与业务组件（职责内聚）
├── data/         静态数据源与数据转换逻辑（单一数据真源）
├── hooks/        复用状态逻辑与生命周期钩子
├── styles/       设计系统全局变量与字体定义
```

组件内部样式应依赖集中定义的设计系统变量，避免随处硬编码魔数颜色与尺寸。

### 晴空设计令牌与 CSS 变量体系

项目全局采用设计系统令牌（Design Tokens）进行样式约束：

* **色阶变量**：`--sky-500`、`--sky-700` 作为品牌主色，`--ink-900`、`--ink-600` 作为文本色阶；
* **语义背景**：`--bg-paper`（页面底色）、`--bg-sunk`（凹槽沉降色）；
* **对比度保障**：正文与背景必须满足 WCAG 2.1 AA 级对比度标准（正文文本对比度不低于 4.5:1）。

### URL Query 状态下沉设计

对于列表筛选、分页、搜索关键字及选项卡切换等状态，推荐将其同步持久化至浏览器地址栏（`URLSearchParams`）：

状态下沉至 URL 能够原生支持浏览器前进后退历史记录导航，并且方便用户将特定筛选视图作为链接直接分享与收藏。

### 交互组件场景契合与无障碍动效

组件交互设计应契合真实业务场景，避免过度装饰：

动效采用微交互原则，过渡时长控制在 150ms~300ms 以内；对于开启了系统减弱动态效果（`prefers-reduced-motion`）的用户，提供平滑的透明度过渡降级方案，保障无障碍访问体验。
