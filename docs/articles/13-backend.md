### 服务端单向依赖分层体系

服务端代码架构遵循严格的单向依赖原则：

```
Controller (控制层)  ──>  Service (业务层)  ──>  Mapper / Repository (持久层)
```

控制层仅负责 HTTP 协议参数绑定、格式校验与响应组装，禁止直接注入 Mapper 访问数据库；业务层负责核心业务规则校验与事务边界控制；持久层专注于数据持久化与 SQL 映射。

### 业务建模与对象解耦

严格分离不同生命周期的数据对象模型：

* **请求传输对象（DTO）**：接收客户端入参，结合校验注解（如 `@Valid`）校验必填项与格式；
* **持久化实体（Entity）**：对应数据库表结构映射，维护数据持久化状态；
* **视图响应对象（VO）**：按前端展示诉求裁剪组装数据，隐藏数据库内部物理主键与敏感字段。

### 文件持久化与容错兜底机制

在执行本地文件存储或数据序列化时，必须保障底层健壮性：

写入文件前检查父级目录是否存在；采用缓冲流提升写入效率；读取解析文件时必须包含完整的异常捕获分支，在遇到文件丢失、格式解析异常或行尾空行时提供预设的空状态或默认配置，避免阻塞整个应用程序启动。

### 全局统一业务异常拦截

建立清晰的分层异常处理机制：

业务层在检测到业务前置条件不满足时，统一抛出携带具体错误码与提示信息的自定义业务异常（如 `BusinessException`）；在 Web 层通过全局异常处理器（`@RestControllerAdvice`）统一捕获并封装为标准化 JSON 响应，生产环境下自动屏蔽底层 SQL 堆栈详情，防止系统内部结构泄露。

### 结构化操作日志与审计规范

对系统核心业务数据的创建、变更与删除操作，统一输出结构化审计日志：

日志写入必须采用追加模式（Append-only），包含标准元数据：时间戳（ISO-8601）、操作人标识、操作行为、目标资源标识与操作结果；记录日志时必须对密码、密钥及手机号等敏感信息进行脱敏处理。
