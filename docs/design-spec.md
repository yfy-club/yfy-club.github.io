## 1. 世界观与命名

### 1.1 设定骨架

社团被设定为一座名为 **「云飞扬 / YFY」** 的技术观测站。五条技术方向各自对应一位**常驻研究员**，一位**向导看板娘**负责接引访客。所有角色为**虚构化名**，不指代任何真实社员。

### 1.2 版权立场（重要）

- **不使用**碧蓝档案 / 原神 / 明日方舟等作品的官方角色名、角色形象、Logo、字体、音效、UI 素材。
- 借鉴的仅是**设计语言**（明亮几何 HUD、halo 光环、扁平色块 + 细描边、留白节奏），这属于风格范畴，不构成侵权。
- 全部立绘为**本工程内原创矢量绘制**，无外部图源。
- 角色名集中于 `src/data/characters.ts`，可随时整体替换。

## 2. 视觉系统

### 2.1 色彩令牌

**基调**：碧蓝档案的明亮几何感为骨，京阿尼日常系的空气感为肉。**全站单一浅色主题，不做深色模式**——晴空调性依赖高亮度底色，深色会摧毁整套色彩关系。

```css
:root {
  /* 底层 —— 晴空三阶，绝不使用纯白 #FFF 大面积铺底 */
  --bg-sky:      #F2F8FD;  /* 页面底 */
  --bg-paper:    #FAFCFE;  /* 卡片面 */
  --bg-sunk:     #E7F1FA;  /* 凹陷槽 / 代码块底 */

  /* 墨色 —— 带蓝的深墨，保持通透，禁止 #000 */
  --ink-900:     #12283A;  /* 主标题 / 正文 */
  --ink-600:     #3D5C74;  /* 次级正文 */
  --ink-400:     #6E8BA1;  /* 辅助说明 / 刻度数字 */

  /* 主色 天蓝 */
  --sky-700:     #14699F;  /* 可承载正文与链接 */
  --sky-500:     #2892D8;  /* 主交互色 / 图形 */
  --sky-300:     #8FCBF0;  /* 导轨、分隔 */
  --sky-100:     #D8EBF9;  /* 大面积浅色块 */

  /* 点缀 浅粉 —— 仅瞬态能量流，静止画面中粉色占比 < 5% */
  --pink-700:    #B02A6B;  /* 唯一可承载文字的粉 */
  --pink-500:    #F472B6;  /* 激活态、磁吸触点、粒子 */
  --pink-300:    #FFB3C7;  /* 柔粉高光 */
  --pink-100:    #FFE4EC;  /* 粉色标签底，唯一能垫 --pink-700 文字的粉 */

  /* 线条 */
  --line-hair:   rgb(18 40 58 / 0.10);   /* 1px 导轨 */
  --line-solid:  rgb(18 40 58 / 0.18);   /* 卡片描边 */
  --line-grid:   rgb(18 40 58 / 0.055);  /* 背景坐标网格 */
  --line-focus:  var(--sky-500);
}
```

**对比度**：`npm run check:contrast` 直接从 `tokens.css` 读色值实测，20 项规则，改色改坏了会失败。当前实测：

| 前景 on 背景 | 实测 | 阈值 | 用途 |
|---|---|---|---|
| `--ink-900` on `--bg-sky` | **14.11** | 7 | 主标题与正文 |
| `--ink-900` on `--bg-paper` | **14.69** | 7 | 卡片内正文 |
| `--ink-600` on `--bg-sky` | 6.58 | 4.5 | 次级正文 |
| `--ink-600` on `--bg-paper` | 6.85 | 4.5 | 卡片内次级正文 |
| `--ink-400` on `--bg-sky` | 3.34 | 3 | 仅限非文本图形与 ≥18.66px 粗体 |
| `--sky-700` on `--bg-sky` | 5.53 | 4.5 | 正文与链接 |
| `--sky-700` on `--sky-100` | 4.84 | 4.5 | Tag sky 底上的文字 |
| `--sky-500` on `--bg-sky` | 3.17 | 3 | 仅限图形、边框、≥24px 大字 |
| `--pink-700` on `--bg-sky` | 5.79 | 4.5 | 粉色文案 |
| `--pink-700` on `--pink-100` | 5.18 | 4.5 | Tag pink 底上的文字 |
| `--bg-paper` on `--sky-700` | 5.75 | 4.5 | Tag solid 反白文字 |
| `--stage-*` on `--bg-sky` | 3.96–4.49 | 3 | 三个展台的框线（WCAG 1.4.11 非文本对比度） |
| `--char-*-accent` on `--bg-sky` | 3.17–4.65 | 3 | 六位角色的 halo 与道具线条（同 1.4.11） |

**禁止承载文字**：`--pink-500`、`--pink-300`、`--sky-300`、`--sky-100`。这条规则写进了 `check-contrast.ts`，不是口头约定。

> M1 修正记录：`--sky-700` 由 `#166FA8` 调深为 `#14699F`、`--sky-500` 由 `#2E9BE0` 调深为 `#2892D8`、新增 `--pink-100`。原因是规格初稿只验了对 `--bg-sky` 的对比度，漏了标签底色上的组合，实测有三项不达标。改的是色值，不是阈值。

### 2.2 字体与字阶

| 用途 | 字体 | 备注 |
|---|---|---|
| 中文标题 | `Noto Sans SC` 700 | |
| 中文正文 / 说明 | `Noto Sans SC` 400 | caption 也走 400，见下方说明 |
| 拉丁 HUD / 数字 / 代号 | `Chakra Petch` 500/600 | 切角几何感，是碧蓝档案味的关键来源 |
| 代码 | `JetBrains Mono` 400 | 仅 `/docs`，按需加载 |

**中文只做 400 与 700 两档字重**（M1 实测后的决定，见第 7 节）：

- **900 不进正文字重表。** 全站唯一需要 display 级重量的是首屏「云飞扬」三个字，单独切一份三字微分片（1.2 KB，`unicode-range` 只开这三个码点），别处一律 400 / 700。原文写的「改走 SVG 轮廓路径」已被 M3 推翻，理由见 4.1 节修正记录。
- **caption 由 500 降为 400。** 多一档字重要多背一整份中文分片（约 40KB），13px 的可读性靠 `letter-spacing` 补，不靠字重。

**字阶**（1.25 模数，视口 `clamp` 流体）：

```
display  clamp(56px, 9vw, 132px)   line-height 0.92  letter-spacing -0.03em  weight 700
h1       clamp(36px, 4.5vw, 60px)  line-height 1.06  letter-spacing -0.02em  weight 700
h2       clamp(26px, 2.6vw, 36px)  line-height 1.18  weight 700
h3       20px                      line-height 1.35  weight 700
body     16px                      line-height 1.85  weight 400
caption  13px                      line-height 1.5   weight 400
hud      11px  Chakra Petch 600    letter-spacing 0.18em  uppercase
```

**排版禁令**：全站不出现 Emoji；不出现 `//` `::` `>` 等伪代码前缀；HUD 标签只使用**真实语义**的短词（`SECTOR 02`、`ORACLE`、`620 CASES`），不编造中二黑话。

### 2.3 栅格与几何

- 栅格：12 列，`gutter 24px`，最大内容宽 `1320px`，两侧安全边 `clamp(20px, 5vw, 88px)`。
- 间距阶：`4 / 8 / 12 / 16 / 24 / 40 / 64 / 104 / 168`（斐波那契近似，节奏更像编辑设计而非后台系统）。
- 圆角：卡片 `14px`；小徽章 `6px`；**关键卡片右上或左下切一个 `18px` 45° 斜角**——这是碧蓝档案几何感最省力也最有效的一招。
- 描边：统一 `1px`（高 DPI 下 `0.5px` 视觉更利），色 `--line-solid`。**卡片默认无阴影**；仅 hover 时给一层 `0 18px 40px -24px rgba(22,111,168,.45)`。

### 2.4 HUD 语汇库（可复用原子）

| 名称 | 形态 | 用途 |
|---|---|---|
| `Rail` | 全幅 1px 水平/垂直导轨，端点带 4px 短刻 | 分区分隔、页面骨架 |
| `Reticle` | 十字准星（两条 10px 线 + 中心 3px 空心方） | 区块锚点、卡片四角 |
| `TickScale` | 垂直刻度尺，每 5 格一长刻 + 数字 | 页面左侧滚动进度 |
| `Tag` | 切角矩形 + `hud` 字体 | 方向代号、技术栈标签 |
| `Bracket` | 四角 L 形取景框（仅角，不闭合） | 聚焦中的项目展台 |
| `Diamond` | 4px 旋转 45° 实心方块 | 列表项目符号（**替代所有 Emoji 与 `-`**） |

### 2.5 光效与材质铁律

上一版最大的败笔是大面积毛玻璃导致整页发白发虚。本版硬性约束：

1. **`backdrop-filter: blur()` 全站仅允许出现在两处**：顶部导航条（`blur(12px)` + `--bg-paper` 88% 不透明）、弹幕输入浮层。其余一律禁止。
2. **禁止大尺寸 CSS 弥散**：任何 `box-shadow` 的 blur 半径 ≤ 40px 且必须带负 spread。禁止 `filter: blur()` 超过 8px 的装饰性色斑。
3. **明暗靠色阶而非模糊**：层次由 `--bg-sky / --bg-paper / --bg-sunk` 三阶 + 1px 描边建立，骨架必须"硬"。
4. **光只在动的时候出现**：辉光、粒子、光栅边缘全部绑定在交互态或滚动进入，静止画面接近纯平面印刷品。
5. 全局叠一层 `opacity: 0.03` 的 SVG 噪点纹理，抵消数字化的塑料感——这是唯一允许的全局叠加层。

## 3. 角色系统（矢量看板娘）

### 3.1 绘制规格

- 形态：**半身矢量看板娘**（胸口以上，约 1:1.15 头身框内）。
- 手法：扁平色块 + `1.5px` 同色系深色描边 + 至多两处线性渐变（发丝、眼球）。**不做厚涂**。
- 尺寸：`viewBox="0 0 480 560"`，全部路径手写，单角色目标 ≤ 18KB（gzip 前）。
- 复用：六位角色共用同一套**骨架 SVG 模板**，换配色、发型 path、halo path、道具 path。这样六人总体积 ≈ 单人 × 1.9，而非 × 6。

> M2 偏离说明：实现没有用 `<use>`，改成**单个参数化 React 组件 + 数据变体**（`src/components/mascot/mascot.tsx` + `src/data/characters.ts`）。
> 理由：`<use>` 的 shadow tree 里外部 CSS 选择器不生效，差分交叉淡入与发丝分组动画就只能全走内联 style。
> 而「六人总体积 ≈ 单人 × 1.9」这个真实目标，源码级共用一份骨架已经完全满足，`<use>` 只多省约 60 个 DOM 节点。

### 3.2 SVG 图层结构（自下而上，z 序即绘制序）

```
g#halo-back        halo 后半环（被头发遮挡的部分）
g#hair-back        后发（含惯性摆动组 .strand-b × 3）
g#body             肩、颈、衣领、领巾
g#face-base        脸型 + 耳
g#blush            腮红（差分：opacity 0 → 1）
g#eyes             ├ .eye-white  眼白（固定）
                   ├ .eye-iris   瞳（差分：path 切换 + 平移跟随鼠标 ±3px）
                   ├ .eye-shine  高光（固定相对瞳）
                   └ .eye-lid    眼睑（差分：path 切换，控制睁闭）
g#brows            眉（差分：path 切换）
g#mouth            嘴（差分：path 切换）
g#hair-front       前发 + 呆毛（惯性组 .strand-f × 2，呆毛 .ahoge 单独更软的弹簧）
g#halo-front       halo 前半环（发光主体）
g#prop             方向道具（ORACLE 的悬浮节点 / FORGE 的六角扳手等）
g#fx               交互粒子挂载点（Canvas 覆盖层锚定于此）
```

差分只切换 `eyes.eye-iris` / `eyes.eye-lid` / `brows` / `mouth` / `blush` 五组，其余保持不变——这是"差分"的正确成本模型。

### 3.3 差分状态机

状态集：`NEUTRAL` `FOCUS` `SURPRISE` `THINK` `SMILE` `IDLE_DAZE` `POUT`

| 触发 | 目标状态 | 说明 |
|---|---|---|
| 初始 / 回到 Hero | `NEUTRAL` | 视线跟随鼠标，每 4–7s 随机眨眼（双眼睑 90ms 闭合 + 60ms 张开） |
| 滚动进入「方向」区 | `FOCUS` | 眉略压，瞳孔偏向卡片方向，身体轻微侧转 2° |
| 滚动进入「项目」区 | `SMILE` | 眼睑下弯，嘴角上扬，腮红 `opacity 0 → 0.5` |
| 滚动进入「文档库」区 | `THINK` | 单眉上挑，视线上飘，呆毛下垂 |
| 悬停某张方向卡 | `FOCUS` + **联动特效** | 见 3.4 |
| 悬停项目卡 | `SURPRISE` | 瞳孔放大 1.15×，嘴张小 O，持续 400ms 后回落至 `SMILE` |
| 连续点击立绘 ≥ 3 次 | `POUT` | 鼓脸、闭一只眼、halo 抖动；5s 无操作后回落 |
| 20s 无鼠标/滚动/键盘 | `IDLE_DAZE` | 眼睑半闭、瞳孔飘向左上、呆毛缓慢下垂；任意输入立即 300ms 回到上一状态 |

转场规则：所有差分切换用 `120ms` 交叉淡入（`opacity` + 3px 位移），**不允许硬切**；同一时刻只允许一个状态生效，新触发抢占旧状态。

### 3.4 悬停方向卡的联动特效

| 悬停卡 | 角色反应 |
|---|---|
| ORACLE（AI） | 瞳内浮出紫色神经节点微光，halo 节点顺序点亮 |
| WEAVER（软件工程） | 眼中映出蓝色齿轮转动，领巾扬起 |
| VAULT（数据库） | 瞳孔浮现三层同心环，画面下沿升起深青栅格 |
| RELAY（云与物联网） | 眼底泛青绿波纹，halo 向外扩散三圈信号 |
| FORGE（工业智能） | 瞳内闪过琥珀火花，肩部投下六角剪影 |

联动动画时长 ≤ 500ms，鼠标移出立即反向播放，**不留残留**。

> M4 修正记录：**联动特效的观看位从 Hero 立绘改到「向导驻留挂件」。**
>
> 原规格默认「悬停方向卡 → Hero 看板娘反应」，但 `.hero` 是 `min-height: 100dvh`，立绘 `align-self: end` 落在里头。
> 滚到 `#tracks` 顶到视口顶时 Hero 已经整块出画——看板娘不在屏幕上，这张表和 3.3 的进区切 `FOCUS/SMILE/THINK` 全是看不见的动作。
>
> 新方案：Hero 出画后 NAVI 缩成右侧固定小挂件常驻，联动特效与进区状态都演在挂件上。
> 空槽实测：1440 视口 `.shell` 外边距 60 + `--content-pad` 72 = 左右各 132px；1280 只有 64px；1760 以上 308px。
> 所以挂件宽度压到 120px，且 `width < 1360` 直接 `display: none`，不压内容。窄屏只隐藏 DOM，状态机照常跑，宽屏一放大立刻看得见。
>
> 样式硬约束：切角面板 + 1px 描边 + `--bg-paper` 实色。**不许圆头像、不许阴影、不许毛玻璃**，否则读成客服气泡。
>
> 特效层实现三种手段，不做原规格逐条描述的全部造型：
> 瞳内映色（`--fx-tone` 驱动 iris 叠色）、halo 反应（`--fx-pulse` 驱动环上装饰的透明度与外扩）、领巾扬起（`--fx-lift` 叠在惯性位移之上）。
> 「画面下沿升起深青栅格」「肩部投下六角剪影」这类需要新增图层的效果不做：它们要往骨架里加 path，与 3.1 的差分成本模型冲突。

### 3.5 惯性物理参数

发丝、领巾、halo 用统一的弹簧跟随（跟随目标 = 鼠标位移 × 增益，或滚动速度）：

| 部件 | stiffness | damping | mass | 增益 |
|---|---|---|---|---|
| 呆毛 `.ahoge` | 70 | 9 | 1.0 | 0.16 |
| 后发 `.strand-b` | 90 | 12 | 0.9 | 0.10 |
| 前发 `.strand-f` | 120 | 14 | 0.8 | 0.07 |
| 领巾 | 100 | 13 | 1.1 | 0.12 |
| halo（延迟跟随头部） | 150 | 18 | 0.7 | 0.05 |
| 身体整体视差 | 200 | 24 | 1.0 | 0.03 |

位移上限统一 clamp 到 `±14px`，避免鼠标甩动时画面散架。

## 4. 页面结构

> M3 修正记录（两条，都是推翻规格原文）：
>
> 1. **字标不走 SVG 轮廓路径，改走 900 三字微分片。** 2.2 节原本判定「为三个字背一整份 900 中文分片不划算」，这个判断建立在「900 = 一整份分片」的前提上，而 `subset-font` 可以只切三个字——实测 `noto-sans-sc-wordmark-900.woff2` 1.2 KB，`unicode-range` 只开这三个码点，别处碰不到 900。手写三个汉字的贝塞尔轮廓换 1.2 KB，不值。语料常量在 `scripts/subset-fonts.ts` 的 `WORDMARK`，改字标必须同步改那里和 `wordmark.tsx`。
> 2. **不用 `writing-mode: vertical-rl`，改成一字一行的 flex 列。** 竖排模式下中文标点与字距要靠 `text-orientation` 二次矫正，而且没法给单字加进入延迟。一字一行的锚点是精确的，`--i` 直接驱动 stagger。
>
> 另：5.3 写粒子画布 `position: fixed`，实现取 `position: absolute` 落在 `.hero` 内。首屏之外本来就不该有粒子，`fixed` 会让画布跟着滚动一路盖到方向卡上；`absolute` + `IntersectionObserver` 暂停 RAF 是同一件事的更省写法。

## 5. 交互与动效规格

### 5.1 弹簧参数总表

| 场景 | stiffness | damping | mass |
|---|---|---|---|
| 卡片原地展开 / 收起 | 260 | 30 | 0.9 |
| 磁吸按钮跟随 | 180 | 18 | 1.0 |
| 3D 卡片倾斜 | 220 | 26 | 1.0 |
| 页面区块进入 | — | — | `duration .45s, ease cubic-bezier(.22,1,.36,1)` |
| 立绘部件 | 见 3.5 | | |

### 5.2 滚动编排

区块进入视口 15% 时启动，内部元素 **stagger 60ms** 依次进入（位移 16px + 淡入）。同一屏内最多 6 个 stagger 单元，超出的不做动画——防止"满屏东西一起飞"的廉价感。

### 5.3 Canvas 引力粒子光场

- 仅在 Hero 区域，`position: fixed` + `pointer-events: none`，滚出视口即暂停 RAF。
- 粒子数：`clamp(40, floor(视口面积 / 22000), 140)`，`devicePixelRatio > 2` 时再 × 0.7。
- 行为：布朗慢漂 + 鼠标 160px 半径内产生引力形变，靠近时粒子转 `--pink-500` 并拉出 ≤ 24px 拖尾；粒子间距 < 90px 时连 1px 细线（透明度按距离衰减）。
- 性能闸门：单帧预算 4ms，超时自动降粒子数 20%，连续三次降级则关闭并保留静态网格。

### 5.4 弹幕系统

访客可发弹幕，**仅存 `localStorage`**。为避免"假互动"欺骗：

- 输入框 placeholder 与提交后的 toast 明确写：**「仅保存在你的浏览器，别人看不到」**。
- 首次进入展示 12 条**预置弹幕**（社团技术梗 / 开发日常），与用户自发的弹幕在样式上区分：预置为 `--ink-400`，自己发的为 `--pink-700` 且带一个 `Diamond` 前标。
- 弹幕轨道：Hero 上方 4 条轨道，`opacity 0.5`，速度 `28–42s` 单次穿屏，字号 13px。默认**关闭**，由顶部开关开启并记忆选择。
- 长度上限 40 字，纯前端过滤空白与控制字符。

### 5.5 声音系统

- 顶栏一枚喇叭开关，**默认静音**，选择记忆在 `localStorage`。
- 音频文件路径预留 `public/audio/bgm.ogg`（+ `bgm.mp3` 兜底）。**文件不存在时开关自动隐藏，不报错、不留死按钮。**
- 首次开启才发起下载（`preload="none"`），淡入 1.2s，音量默认 0.35，页面隐藏时自动暂停。
- 体积预算 ≤ 2.5MB（128kbps Opus/Vorbis）。
- 合规音源清单见 `docs/music-sources.md`。**本工程不会自带任何第三方音频文件，由你确认授权后自行放入。**
- 本版**不做 UI 点击音效**（按你的选择）。

### 7.2 字体预算（M1 实测重定）

规格初稿写的「字体总计 ≤ 120 KB」是拍脑袋的数，没量过。实测后推翻重定。

**推翻过程**：Fontsource 的 Noto Sans SC 中文包是整块 1.1MB，不按 unicode-range 切片。第一版按 400/700/900 三档字重、语料含全部 Markdown 扫出 964 字，产出 **446 KB**，是预算的 3.7 倍。三处根因：把不上线的内部规格文档扫进了语料；代码注释里的中文不会上线却算进了语料；700/900 是标题字重，不该背长文语料。

**重构后**：语料按作用域切成 `ui` 与 `docs` 两份，`docs` 分片只装 ui 语料里没有的字，靠 `unicode-range` 让浏览器在首屏根本不去下载它。字重砍到 400/700 两档（理由见 2.2）。

当前实测（M4 后，`npm run fonts:subset`）：

| | 文件 | 体积 |
|---|---|---|
| 首屏 | `noto-sans-sc-latin-400` | 8.5 KB |
| 首屏 | `noto-sans-sc-cjk-400-ui`（375 字） | 51.9 KB |
| 首屏 | `noto-sans-sc-latin-700` | 8.6 KB |
| 首屏 | `noto-sans-sc-cjk-700-ui`（307 字） | 43.8 KB |
| 首屏 | `noto-sans-sc-wordmark-900`（仅「云飞扬」三字） | 1.2 KB |
| 首屏 | Chakra Petch 500 / 600 | 19.4 KB |
| | **首屏合计** | **133.5 KB** / 预算 **160 KB** |
| 按需 | `noto-sans-sc-cjk-400-lab` / `-700-lab`（103 字） | 16.1 + 16.3 KB |
| 按需 | `noto-sans-sc-cjk-400-docs` / `-700-docs`（236 字） | 35.4 + 36.1 KB |
| 按需 | JetBrains Mono（仅 `/docs`） | 39.5 KB |

> M4 修正记录：**语料从两个作用域拆成三个，并给 700 单独一份语料。**
>
> M4 把方向卡与展台文案落地后 ui 语料从 293 字涨到 478 字，首屏 170.2 KB，超预算 10.2 KB，脚本直接 exit(1)。
> 两个杠杆，都不动预算：
>
> 1. **新增 `lab` 作用域。** `expressions.ts` 的 `intent` 与 `hair.ts` 的 `silhouette` 是给 `?lab=1` 验收页看的说明串，
>    跟着 mascot 模块进了 JS 包但首屏不渲染。它们在 ui 语料里占 103 字 = 首屏 32.4 KB，为一个内部工具页背的。
>    现在走 `unicode-range` 按需下载。
> 2. **700 只装 307 字。** 400 与 700 共用一份语料时每个新字收两遍钱。能力关键词、项目简介、副标题全部走 400，
>    从未用粗体渲染。`BODY_ONLY_FIELDS` 按字段把它们敲下来，只剔除「只在正文出现」的字（实测 68 个）。
>    被剔的字在 700 没有对应 face，浏览器拿 400 那份上——这些字本来就不会用粗体渲染。
>
