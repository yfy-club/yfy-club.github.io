## 2. 视觉系统

### 2.1 色彩令牌

**基调**：碧蓝档案的明亮几何感为骨，京阿尼日常系的空气感为肉。**全站单一浅色主题，不做深色模式**——晴空调性依赖高亮度底色，深色会摧毁整套色彩关系。

```css
:root {
  /* 底层 —— 晴空三阶，绝不使用纯白 #FFF 大面积铺底 */
  --bg-sky:      #F2F8FD;  /* 页面底 */
  --bg-paper:    #FAFCFE;  /* 卡片面 */
  --bg-sunk:     #E7F1FA;  /* 凹陷槽 / 代码块底 */

  /* 墨色 —— 带蓝的深墨，保持通透，禁止 #000 */
  --ink-900:     #12283A;  /* 主标题 / 正文 */
  --ink-600:     #3D5C74;  /* 次级正文 */
  --ink-500:     #4D6C84;  /* HUD 小字 / caption（M7 新增，见修正记录） */
  --ink-400:     #6E8BA1;  /* 仅非文本图形，任何字号的文本都不许用 */

  /* 主色 天蓝 */
  --sky-700:     #14699F;  /* 可承载正文与链接 */
  --sky-500:     #2892D8;  /* 主交互色 / 图形 */
  --sky-300:     #8FCBF0;  /* 导轨、分隔 */
  --sky-100:     #D8EBF9;  /* 大面积浅色块 */

  /* 点缀 浅粉 —— 仅瞬态能量流，静止画面中粉色占比 < 5% */
  --pink-700:    #B02A6B;  /* 唯一可承载文字的粉 */
  --pink-500:    #F472B6;  /* 激活态、磁吸触点、粒子 */
  --pink-300:    #FFB3C7;  /* 柔粉高光 */
  --pink-100:    #FFE4EC;  /* 粉色标签底，唯一能垫 --pink-700 文字的粉 */

  /* 线条 */
  --line-hair:   rgb(18 40 58 / 0.10);   /* 1px 导轨 */
  --line-solid:  rgb(18 40 58 / 0.18);   /* 卡片描边 */
  --line-grid:   rgb(18 40 58 / 0.055);  /* 背景坐标网格 */
  --line-focus:  var(--sky-500);
}
```

### 2.2 字体与字阶

| 用途 | 字体 | 备注 |
|---|---|---|
| 中文标题 | `Noto Sans SC` 700 | |
| 中文正文 / 说明 | `Noto Sans SC` 400 | caption 也走 400，见下方说明 |
| 拉丁 HUD / 数字 / 代号 | `Chakra Petch` 500/600 | 切角几何感，是碧蓝档案味的关键来源 |
| 代码 | `JetBrains Mono` 400 | 仅 `/docs`，按需加载 |

**中文只做 400 与 700 两档字重**（M1 实测后的决定，见第 7 节）：

- **900 不进正文字重表。** 全站唯一需要 display 级重量的是首屏「云飞扬」三个字，单独切一份三字微分片（1.2 KB，`unicode-range` 只开这三个码点），别处一律 400 / 700。原文写的「改走 SVG 轮廓路径」已被 M3 推翻，理由见 4.1 节修正记录。
- **caption 由 500 降为 400。** 多一档字重要多背一整份中文分片（约 40KB），13px 的可读性靠 `letter-spacing` 补，不靠字重。

**字阶**（1.25 模数，视口 `clamp` 流体）：

```
display  clamp(56px, 9vw, 132px)   line-height 0.92  letter-spacing -0.03em  weight 700
h1       clamp(36px, 4.5vw, 60px)  line-height 1.06  letter-spacing -0.02em  weight 700
h2       clamp(26px, 2.6vw, 36px)  line-height 1.18  weight 700
h3       20px                      line-height 1.35  weight 700
body     16px                      line-height 1.85  weight 400
caption  13px                      line-height 1.5   weight 400
hud      11px  Chakra Petch 600    letter-spacing 0.18em  uppercase
```

**排版禁令**：全站不出现 Emoji；不出现 `//` `::` `>` 等伪代码前缀；HUD 标签只使用**真实语义**的短词（`SECTOR 02`、`ORACLE`、`620 CASES`），不编造中二黑话。

### 2.3 栅格与几何

- 栅格：12 列，`gutter 24px`，最大内容宽 `1320px`，两侧安全边 `clamp(20px, 5vw, 88px)`。
- 间距阶：`4 / 8 / 12 / 16 / 24 / 40 / 64 / 104 / 168`（斐波那契近似，节奏更像编辑设计而非后台系统）。
- 圆角：卡片 `14px`；小徽章 `6px`；**关键卡片右上或左下切一个 `18px` 45° 斜角**——这是碧蓝档案几何感最省力也最有效的一招。
- 描边：统一 `1px`（高 DPI 下 `0.5px` 视觉更利），色 `--line-solid`。**卡片默认无阴影**；仅 hover 时给一层 `0 18px 40px -24px rgba(22,111,168,.45)`。

### 2.4 HUD 语汇库（可复用原子）

| 名称 | 形态 | 用途 |
|---|---|---|
| `Rail` | 全幅 1px 水平/垂直导轨，端点带 4px 短刻 | 分区分隔、页面骨架 |
| `Reticle` | 十字准星（两条 10px 线 + 中心 3px 空心方） | 区块锚点、卡片四角 |
| `TickScale` | 垂直刻度尺，每 5 格一长刻 + 数字 | 页面左侧滚动进度 |
| `Tag` | 切角矩形 + `hud` 字体 | 方向代号、技术栈标签 |
| `Bracket` | 四角 L 形取景框（仅角，不闭合） | 聚焦中的项目展台 |
| `Diamond` | 4px 旋转 45° 实心方块 | 列表项目符号（**替代所有 Emoji 与 `-`**） |

### 2.5 光效与材质铁律

上一版最大的败笔是大面积毛玻璃导致整页发白发虚。本版硬性约束：

1. **`backdrop-filter: blur()` 全站仅允许出现在两处**：顶部导航条（`blur(12px)` + `--bg-paper` 88% 不透明）、弹幕输入浮层。其余一律禁止。
2. **禁止大尺寸 CSS 弥散**：任何 `box-shadow` 的 blur 半径 ≤ 40px 且必须带负 spread。禁止 `filter: blur()` 超过 8px 的装饰性色斑。
3. **明暗靠色阶而非模糊**：层次由 `--bg-sky / --bg-paper / --bg-sunk` 三阶 + 1px 描边建立，骨架必须"硬"。
4. **光只在动的时候出现**：辉光、粒子、光栅边缘全部绑定在交互态或滚动进入，静止画面接近纯平面印刷品。
5. 全局叠一层 `opacity: 0.03` 的 SVG 噪点纹理，抵消数字化的塑料感——这是唯一允许的全局叠加层。

>   环那么宽得下探到眼睛高度，那时环已经不是 halo 是项圈。改成靠**呆毛**穿过环：
>   六人的呆毛尖都高过环上缘，穿过去那一段就是纵深。
> - **呼吸。** 静止画面里「活着」的唯一来源，4.6s 一轮，纵向 0.6% 位移 + 0.6% 拉伸。
>   halo 的那一路错开 0.9s，同相位就是一整块贴纸在动。
> - **轮廓光。** `drop-shadow` 吃 alpha，沿剪影描一圈主调，只在交互时出现（2.5 第 4 条）。
> - **响应式图片。** 立绘改用 HTML `<img>` 而不是 SVG `<image>`，为的就是 srcset / sizes /
>   loading / fetchpriority 这四样。详见 7.3。

### 3.1 绘制规格

- 形态：**半身矢量看板娘**（胸口以上，约 1:1.15 头身框内）。
- 手法：扁平色块 + `1.5px` 同色系深色描边 + 至多两处线性渐变（发丝、眼球）。**不做厚涂**。
- 尺寸：`viewBox="0 0 480 560"`，全部路径手写，单角色目标 ≤ 18KB（gzip 前）。
- 复用：六位角色共用同一套**骨架 SVG 模板**，换配色、发型 path、halo path、道具 path。这样六人总体积 ≈ 单人 × 1.9，而非 × 6。

> M2 偏离说明：实现没有用 `<use>`，改成**单个参数化 React 组件 + 数据变体**（`src/components/mascot/mascot.tsx` + `src/data/characters.ts`）。
> 理由：`<use>` 的 shadow tree 里外部 CSS 选择器不生效，差分交叉淡入与发丝分组动画就只能全走内联 style。
> 而「六人总体积 ≈ 单人 × 1.9」这个真实目标，源码级共用一份骨架已经完全满足，`<use>` 只多省约 60 个 DOM 节点。

### 3.2 SVG 图层结构（自下而上，z 序即绘制序）

```
g#halo-back        halo 后半环（被头发遮挡的部分）
g#hair-back        后发（含惯性摆动组 .strand-b × 3）
g#body             肩、颈、衣领、领巾
g#face-base        脸型 + 耳
g#blush            腮红（差分：opacity 0 → 1）
g#eyes             ├ .eye-white  眼白（固定）
                   ├ .eye-iris   瞳（差分：path 切换 + 平移跟随鼠标 ±3px）
                   ├ .eye-shine  高光（固定相对瞳）
                   └ .eye-lid    眼睑（差分：path 切换，控制睁闭）
g#brows            眉（差分：path 切换）
g#mouth            嘴（差分：path 切换）
g#hair-front       前发 + 呆毛（惯性组 .strand-f × 2，呆毛 .ahoge 单独更软的弹簧）
g#halo-front       halo 前半环（发光主体）
g#prop             方向道具（ORACLE 的悬浮节点 / FORGE 的六角扳手等）
g#fx               交互粒子挂载点（Canvas 覆盖层锚定于此）
```

差分只切换 `eyes.eye-iris` / `eyes.eye-lid` / `brows` / `mouth` / `blush` 五组，其余保持不变——这是"差分"的正确成本模型。

### 3.3 差分状态机

状态集：`NEUTRAL` `FOCUS` `SURPRISE` `THINK` `SMILE` `IDLE_DAZE` `POUT`

| 触发 | 目标状态 | 说明 |
|---|---|---|
| 初始 / 回到 Hero | `NEUTRAL` | 视线跟随鼠标，每 4–7s 随机眨眼（双眼睑 90ms 闭合 + 60ms 张开） |
| 滚动进入「方向」区 | `FOCUS` | 眉略压，瞳孔偏向卡片方向，身体轻微侧转 2° |
| 滚动进入「项目」区 | `SMILE` | 眼睑下弯，嘴角上扬，腮红 `opacity 0 → 0.5` |
| 滚动进入「文档库」区 | `THINK` | 单眉上挑，视线上飘，呆毛下垂 |
| 悬停某张方向卡 | `FOCUS` + **联动特效** | 见 3.4 |
| 悬停项目卡 | `SURPRISE` | 瞳孔放大 1.15×，嘴张小 O，持续 400ms 后回落至 `SMILE` |
| 连续点击立绘 ≥ 3 次 | `POUT` | 鼓脸、闭一只眼、halo 抖动；5s 无操作后回落 |
| 20s 无鼠标/滚动/键盘 | `IDLE_DAZE` | 眼睑半闭、瞳孔飘向左上、呆毛缓慢下垂；任意输入立即 300ms 回到上一状态 |

转场规则：所有差分切换用 `120ms` 交叉淡入（`opacity` + 3px 位移），**不允许硬切**；同一时刻只允许一个状态生效，新触发抢占旧状态。

| 悬停卡 | 角色反应 |
|---|---|
| ORACLE（AI） | 瞳内浮出紫色神经节点微光，halo 节点顺序点亮 |
| WEAVER（软件工程） | 眼中映出蓝色齿轮转动，领巾扬起 |

> 瞳内映色（`--fx-tone` 驱动 iris 叠色）、halo 反应（`--fx-pulse` 驱动环上装饰的透明度与外扩）、领巾扬起（`--fx-lift` 叠在惯性位移之上）。

### 3.5 惯性物理参数

发丝、领巾、halo 用统一的弹簧跟随（跟随目标 = 鼠标位移 × 增益，或滚动速度）：

| 部件 | stiffness | damping | mass | 增益 |
|---|---|---|---|---|
| 呆毛 `.ahoge` | 70 | 9 | 1.0 | 0.16 |
| 后发 `.strand-b` | 90 | 12 | 0.9 | 0.10 |
| 前发 `.strand-f` | 120 | 14 | 0.8 | 0.07 |
| 领巾 | 100 | 13 | 1.1 | 0.12 |
| halo（延迟跟随头部） | 150 | 18 | 0.7 | 0.05 |
| 身体整体视差 | 200 | 24 | 1.0 | 0.03 |

位移上限统一 clamp 到 `±14px`，避免鼠标甩动时画面散架。

> | 对比度 | 14.11 | 7.57 | **5.54** | 4.07 | 3.06 | **2.08** |
>
> 规格原值 `.35` 只有 2.08:1，远低于 2.1 表要求的 4.5，也与第 6 节「全部文本 ≥ AA」冲突。
> 虚焦是暂时状态，但用户按 `Ctrl+F` 找页内文本、或只想扫一眼全文时它就是当前可见内容，按 WCAG 口径仍然是文本。
> 抬到 `.7` 得 5.54:1 过 AA。虚实差别改由 `blur(3px)` 承担——3px 模糊落在 16px 正文上已经完全读不出字形，观感照旧是「一段清晰其余虚」。
>
> 连带一条：`--ink-600` 在 `.7` 下只有 3.32:1，**次级正文、表格、代码块、图注一律不参与虚焦**，
> 聚焦动画只作用于 `--ink-900` 的正文段落与三级标题。虚焦段落里不出现 `--ink-600`。

> M5 修正记录二：**Shiki 走构建期脚本写进 `src/data/docs.ts`，高亮压到三色，且注释色改用 `--ink-600`。**
>
> 规格只写了「轻量 Shiki 预渲染」，没定形态。落成与 `shots.generated.ts` / `fonts.css` 同一套路：
> `npm run docs:build` 跑一次，产物提交进仓库，`shiki` 只在 devDependencies，运行时零成本，不进包。
>
> 配色不用 Shiki 自带主题——它自带的全是深色系或 GitHub 浅色系，跟晴空令牌不是一套色，
> 9 个代码块弄出五颜六色反而破坏调性。压到四色，全部引本站令牌：
>
> | 角色 | 令牌 | 对 `--bg-sunk` |
> |---|---|---|
> | 关键字 / 命令名 | `--ink-900` 700 | 13.21 |
> | 字符串 / 路径 / 数字 | `--sky-700` | 5.17 |
> | 注释 | `--ink-600` | 6.16 |
> | 其余正文 | `--ink-900` | 13.21 |
>
> 注释原打算用 `--ink-400`，实测对 `--bg-sunk` 只有 3.13:1，低于 AA，且 2.1 节把 `--ink-400` 限死在
> 「≥18.66px 粗体或非文本图形」，代码注释是 14px 常规文本，用了就是违规。改 `--ink-600`。
> 注释也不加斜体：Noto Sans SC 没有意大利体，浏览器给中文合成伪斜，而这批代码块的注释恰好全是中文。截图看过，糊。
> 高亮色硬编码在产物 HTML 里，`check:contrast` 只扫 `tokens.css`，管不到它们——所以这张表就是它们的门禁，改色先回来改这里。

## 5. 交互与动效规格

### 5.1 弹簧参数总表

| 场景 | stiffness | damping | mass |
|---|---|---|---|
| 卡片原地展开 / 收起 | 260 | 30 | 0.9 |
| 磁吸按钮跟随 | 180 | 18 | 1.0 |
| 3D 卡片倾斜 | 220 | 26 | 1.0 |
| 页面区块进入 | — | — | `duration .45s, ease cubic-bezier(.22,1,.36,1)` |
| 立绘部件 | 见 3.5 | | |

### 5.2 滚动编排

区块进入视口 15% 时启动，内部元素 **stagger 60ms** 依次进入（位移 16px + 淡入）。同一屏内最多 6 个 stagger 单元，超出的不做动画——防止"满屏东西一起飞"的廉价感。

### 5.3 Canvas 引力粒子光场

- 仅在 Hero 区域，`position: fixed` + `pointer-events: none`，滚出视口即暂停 RAF。
- 粒子数：`clamp(40, floor(视口面积 / 22000), 140)`，`devicePixelRatio > 2` 时再 × 0.7。
- 行为：布朗慢漂 + 鼠标 160px 半径内产生引力形变，靠近时粒子转 `--pink-500` 并拉出 ≤ 24px 拖尾；粒子间距 < 90px 时连 1px 细线（透明度按距离衰减）。
- 性能闸门：单帧预算 4ms，超时自动降粒子数 20%，连续三次降级则关闭并保留静态网格。

### 5.4 弹幕系统

访客可发弹幕，**仅存 `localStorage`**。为避免"假互动"欺骗：

- 输入框 placeholder 与提交后的 toast 明确写：**「仅保存在你的浏览器，别人看不到」**。
- 首次进入展示 12 条**预置弹幕**（社团技术梗 / 开发日常），与用户自发的弹幕在样式上区分：预置为 `--ink-600`，自己发的为 `--pink-700` 且带一个 `Diamond` 前标。
- 弹幕轨道：Hero 上方 4 条轨道，速度 `28–42s` 单次穿屏，字号 13px。默认**关闭**，由顶部开关开启并记忆选择。
- 长度上限 40 字，纯前端过滤空白与控制字符。
- 输入浮层是全站唯二允许 `backdrop-filter` 的地方之一（见 2.5 第 1 条）。

> M6 修正记录一：**轨道 z 序由「立绘之上」（`--z-danmaku: 30`）沉到「内容之下、粒子之上」（`5`）。**
> 实测 Hero 里能容下四条轨道又不压到字标与立绘的全宽自由带：1440×900 只有 `63..188` 共 125px，
> 1440×720 只有 110px，而移动端 390×844 从导航条下沿 55 到字标顶 77 只有 22px。
> 压在内容之上时移动端必然横穿 900 字重的字标，桌面端在矮视口里会压到立绘光环——
> M3 与 M4 都在"压到脸上"这件事上栽过。沉下去之后弹幕从字标与立绘背后穿过，
> 四条轨道在任何视口都不与前景冲突，`elementFromPoint` 逐轨复验过遮挡关系。
>
> M6 修正记录二：**预置弹幕色 `--ink-400` 改 `--ink-600`，轨道 `opacity 0.5` 取消。**
> 两处都是可读性问题。`--ink-400` 对 `--bg-sky` 实测 3.34:1，且 2.1 明令它只能用于
> ≥18.66px 粗体或非文本图形，而弹幕是 13px 常规字重的可读文本。
> `opacity 0.5` 更严重：半透明后的实际颜色是前景与底色的中值，
> 在 `--bg-sky` 上**即使前景取纯黑，上限也只有 3.92:1**，低于 AA 的 4.5——
> "0.5 不透明度 + AA"在这张底色上无解，不是调色能救的。
> 层次改由色阶（`--ink-600` 6.58:1 对正文 `--ink-900` 14.11:1）与 z 序承担。
> 自发弹幕的 `--pink-700` 同理只能实色，5.79:1。
>
> M6 修正记录三：**减弱动效下不只关轨道，连开关一起不出。**
> 第 6 节要求这里"关闭弹幕"，但留一枚点了没反应的按钮，与 5.5 的"不留死按钮"是同一条道理。
> 轨道层与两枚按钮全部等挂载后再渲染，预渲染产物里没有它们，注水不会错位。

### 5.5 声音系统

- 顶栏一枚喇叭开关，**默认静音**，选择记忆在 `localStorage`。
- 音频文件路径预留 `public/audio/bgm.ogg`（+ `bgm.mp3` 兜底）。**文件不存在时开关自动隐藏，不报错、不留死按钮。**
- 首次开启才发起下载（`preload="none"`），淡入 1.2s，音量默认 0.35，页面隐藏时自动暂停。
- 体积预算 ≤ 2.5MB（128kbps Opus/Vorbis）。
- 合规音源清单见 `docs/music-sources.md`。**本工程不会自带任何第三方音频文件，由你确认授权后自行放入。**
- 本版**不做 UI 点击音效**（按你的选择）。
- 署名落位两处：`docs/CREDITS.md` 与页脚。页脚那一行由 `src/data/credits.ts` 的 `BGM_CREDIT` 控制，为 `null` 时整行不出现。

> M6 修正记录：**"文件在不在"改在构建期扫，不在运行时探。**
> 先按运行时 `HEAD` 探测实现过一版，能用，但文件不在时那两个请求会在**每位访客的控制台里各留一条 404**——
> 本节写的是"不报错、不留死按钮"，那两条红字就是报错。
> 顺带一提，运行时探还必须连 `content-type` 一起验：vite dev server 对不存在的路径回的是
> `200 + text/html`（SPA fallback），只看状态码会把那张 HTML 当成音频，拖到 `play()` 才炸。
> 改成 `vite.config.ts` 的 `define` 注入 `__BGM_SOURCES__` 后，零请求、零控制台噪声，
> 客户端只用 `canPlayType` 在 ogg 与 mp3 之间挑一个。
> 代价是 dev 下新放进文件要重启 server 才认——`public/` 的增删本来就不触发重启。
>
> 播放器 `preload="none"`，首次开启才真正 `GET`——实测放了文件后的请求序列是
> 加载时零请求、点开关时一条 `GET bgm.ogg`。
>
> 记忆为开时会尝试自动续播，但浏览器的自动播放策略可能拒绝。
> 被拒时**把开关拨回静音并改写 `localStorage`**，不留"写着开却没声音"的假状态。

| 项 | 要求 |
|---|---|
| `prefers-reduced-motion` | 关闭：粒子光场、视差、立绘惯性、滚动聚焦、弹幕（连开关一并不出，见 5.4 修正记录三）。保留：淡入与展开（缩短至 150ms 线性） |

> M7 修正记录一：**对比度回归不接 axe，改用落地实算探针 `scripts/a11y-probe.mjs`，且不进 `npm run check`。**
>
> 规格原文写「CI 中用 axe 做回归」。两处对不上：
>
> 1. **axe 查不到本工程的真实缺口。** `npm run check:contrast` 只扫 `tokens.css` 的两两组合，
>    axe 扫的是渲染后的 DOM——两者之间有一块谁都不管的地带：**令牌用对了但用错了场合**。
>    `--ink-400` 那 17 处就在这里，axe 会把 11px/600 判成"小字"照样报，但它报不出
>    「这个令牌在 2.1 表里被限死在非文本图形」这条本工程自己的规矩。
> 2. **装 playwright 的代价。** 本工程没装，前三个里程碑都借主站的 `node_modules/.bin/playwright`。
>    `@axe-core/playwright` + `playwright` 进 devDependencies 会让 `npm ci` 多下一整套浏览器。
>
> 落地：`scripts/a11y-probe.mjs`，借主站的 playwright 跑（`PW_ROOT` 指过去），**71 条断言**，六组：
>
> | 组 | 查什么 |
> |---|---|
> | `contrast` | 遍历 `body *`，沿祖先链合成 rgba alpha 与 opacity，实算前景/背景比，按 WCAG 大字规则取 3 或 4.5 |
> | `keyboard` | 焦点环实测 `outlineWidth` / `outlineOffset`；连按 Tab 核对五张方向卡与三个展台全部可达；Enter 展开 Esc 收起 |
> | `aria` | 立绘 SVG 与 92 个 HUD 原子全部在 `aria-hidden` 子树内；卡片是真实 `button[aria-expanded]`；标题层级不跳级 |

> | `forbidden` | `backdrop-filter` 只准两处（要先滚一段，导航条不到 `data-lifted` 不上毛玻璃）、`box-shadow` 负 spread、装饰 blur ≤ 8px |
> | `console` | 每轮挂 `console` / `pageerror` / `requestfailed` / `response>=400` |
>
> **不进 `npm run check`**：它依赖外部仓库的 playwright 与一个跑着的 dev server，塞进门禁会让
> 换机器的人第一条命令就红。四道门禁保持 typecheck / 对比度 / 字体 / 构建不变。改了交互层手动跑。

> M7 修正记录二：**四项实测缺口，全部由探针抓出，已修。**
>
> 第 6 节这张表在 M6 之前只有「弹幕」「屏幕阅读器」两行验过，其余是历次里程碑顺手做的。系统性回归后：
>
> | 缺口 | 规格要求 | 实测 | 修法 |
> |---|---|---|---|
> | 展台不响应 Esc | 全部卡片 Esc 收起 | 方向卡有，三个展台漏了 | `projects.tsx` 加 `keydown` 监听，挂 window 而不是 article——展开后焦点可能已在分层列表里 |
> | 粒子画布留在 DOM | reduce 下关闭粒子 | effect 里提前 return，`<canvas>` 空着挂在那儿 | 组件级 `if (reduced) return null`，改走 `useReducedMotion()`，首帧一律 false 不破注水 |
> | `/docs` 标题从 h2 起跳 | 读屏可按标题导航 | 目录树的分类名是 `h2` 且 DOM 序在 `<main>` 的 `h1` 之前，整页第一个标题成了 h2 | 分类名改 `<p>`（它是导航分组标签，语义由 `nav[aria-label]` 承担）；长文节标题 `h3` → `h2`，class 与 id 不动 |

### 7.2 字体预算（M1 实测重定）

规格初稿写的「字体总计 ≤ 120 KB」是拍脑袋的数，没量过。实测后推翻重定。

**推翻过程**：Fontsource 的 Noto Sans SC 中文包是整块 1.1MB，不按 unicode-range 切片。第一版按 400/700/900 三档字重、语料含全部 Markdown 扫出 964 字，产出 **446 KB**，是预算的 3.7 倍。三处根因：把不上线的内部规格文档扫进了语料；代码注释里的中文不会上线却算进了语料；700/900 是标题字重，不该背长文语料。

**重构后**：语料按作用域切成 `ui` 与 `docs` 两份，`docs` 分片只装 ui 语料里没有的字，靠 `unicode-range` 让浏览器在首屏根本不去下载它。字重砍到 400/700 两档（理由见 2.2）。

当前实测（M5 后，`npm run fonts:subset`）：

| | 文件 | 体积 |
|---|---|---|
| 首屏 | `noto-sans-sc-latin-400` | 8.5 KB |
| 首屏 | `noto-sans-sc-cjk-400-ui`（379 字） | 52.2 KB |
| 首屏 | `noto-sans-sc-latin-700` | 8.6 KB |
| 首屏 | `noto-sans-sc-cjk-700-ui`（313 字） | 44.3 KB |
| 首屏 | `noto-sans-sc-wordmark-900`（仅「云飞扬」三字） | 1.2 KB |
| 首屏 | Chakra Petch 500 / 600 | 19.4 KB |
| | **首屏合计** | **134.3 KB** / 预算 **160 KB** |
| 按需 | `noto-sans-sc-cjk-400-lab` / `-700-lab`（103 字） | 16.1 + 16.3 KB |
| 按需 | `noto-sans-sc-cjk-400-docs` / `-700-docs`（224 字） | 34.1 + 34.4 KB |

> M4 修正记录：**语料从两个作用域拆成三个，并给 700 单独一份语料。**
>
> M4 把方向卡与展台文案落地后 ui 语料从 293 字涨到 478 字，首屏 170.2 KB，超预算 10.2 KB，脚本直接 exit(1)。
> 两个杠杆，都不动预算：
>
> 1. **新增 `lab` 作用域。** `expressions.ts` 的 `intent` 与 `hair.ts` 的 `silhouette` 是给 `?lab=1` 验收页看的说明串，
>    跟着 mascot 模块进了 JS 包但首屏不渲染。它们在 ui 语料里占 103 字 = 首屏 32.4 KB，为一个内部工具页背的。
>    现在走 `unicode-range` 按需下载。
> 2. **700 只装 307 字。** 400 与 700 共用一份语料时每个新字收两遍钱。能力关键词、项目简介、副标题全部走 400，
>    从未用粗体渲染。`BODY_ONLY_FIELDS` 按字段把它们敲下来，只剔除「只在正文出现」的字（实测 68 个）。
>    被剔的字在 700 没有对应 face，浏览器拿 400 那份上——这些字本来就不会用粗体渲染。
>
> 两条加起来从 170.2 降到 133.5 KB，余量 26.5 KB。
> 新增正文字段往 `scripts/subset-fonts.ts` 的 `BODY_ONLY_FIELDS` 加一行，不要抬 `BUDGET_KB`。

> M7 记录：**`docs` 分片的优先级抬到 `lab` 之前**，且 `src/lib/page-title.ts` 三个作用域一起跳过。
>
> 两组作用域有 30 个字重叠（`小随着两注单独飘红口七贴六只直长短切外静具处移带身满超意尾由`）。
> `unicode-range` 不许交叠，谁排在前谁独占那份 face，排在后的那组要用这些字就得连带下前一组整份分片。
> 原先 `lab` 在前，于是**每个访问 `/docs` 的人都要多下 23 KB 的 lab 分片**，只为那 30 个字。
> `/docs` 是给所有人看的正式路由，`?lab=1` 是内部验收页——换过来之后 docsOnly 193 → 223 字，

### 7.3 运行时预算（Lighthouse 移动端）

> M8 记录：**角色立绘从矢量改成栅格图，这一节多出「实际下载量」两行。**
>
> 换图那一版把六张 WebP 塞在 SVG `<image href>` 里，一共 800 KB，
> 且 `public/images/characters/` 里还留着 4.7 MB 的无损 PNG 原稿——它们会原样进 `dist/` 部署。
> SVG `<image>` 拿不到 srcset / sizes / loading / fetchpriority 这四样，
> 等于六张图全按最大档、全部 eager、首屏 LCP 元素还没法预载。而 LCP 本来就 2.87s 不达标。
>
> 四条改法：
>
> 1. **PNG 原稿移出 `public/`**，改放 `assets-src/characters/`，由 `npm run portraits:build`
>    切成 800 / 512 / 256 三档 WebP。部署产物少 4.7 MB。
> 2. **立绘改用 HTML `<img>`**（halo 仍是两层 SVG，压在图上下），拿回那四个属性。
> 3. **`sizes` 按栅格算，不拍脑袋。** 内容区 1144 / 12 栏，大卡 span 5 → 立绘 278px，
>    小卡 span 4 → 146px，挂件 104px，Hero `clamp(340px, 48vw, 700px)`。
>    实测 1440 视口 2× DPR 下浏览器挑档：NAVI / ORACLE / WEAVER 取 800w，
>    VAULT / RELAY / FORGE 取 512w，合计 392 KB，其中首屏只有 NAVI 一张。
> 4. **Hero 的 NAVI 在 `index.html` 预载**，`imagesrcset` / `imagesizes` 与组件里的
>    `SIZES.full` 保持逐字一致——两边一旦漂移，预载与 `<img>` 会挑到不同档位，下两遍。
>
> 顺带修掉一个字体语料的洞：`scripts/subset-fonts.ts` 的 `stripComments()` 对 `.html`
> 是整份原样返回的，往 `index.html` 写一段中文维护注释就白背 6.9 KB 首屏字体
> （实测首屏 141.5 → 148.4 KB）。现在 HTML 注释也一起剥掉。**注释不上屏，不该进语料。**

量法：`npm run build` 出产物，起一个**没有 SPA fallback 的静态服务器**（对文本资源开 gzip，
`/assets/` 给长缓存，HTML 给短缓存——照抄 GitHub Pages 的响应头，否则量到的是 469 KB 原始 JS
而不是 153.7 KB 的实际传输量），再跑 `lighthouse --form-factor=mobile --throttling-method=simulate`。
**不要用 `vite preview`**：它的 SPA fallback 会把 404 那条掩盖掉。

> M7 记录一：**LCP 三条路由全部超 2.0s，超的那部分是 Lighthouse 模拟节流的固定开销，不是页面的。**
>
> 同一次运行里两套数并存：
>
> | | 模拟口径（计分用） | 浏览器实际观测 |
> |---|---|---|
> | `/` FCP | 911ms | **295ms** |
> | `/` LCP | 2863ms | **332ms** |
> | TTFB | 455ms | 2.4ms |
>
> 模拟口径把 150ms RTT、1.6 Mbps 带宽、CPU×4 套在实测的资源图上重算一遍。
> 拿一张**没有任何外部资源的纯 HTML** 在同一台机器上量，下限就是 TTFB 457ms / FCP 636ms / LCP 765ms——
> 也就是说这套节流参数下 LCP 的地板接近 0.8s，而本站首屏要下 149 KB JS + 17 KB CSS + 141 KB 字体。
>
> 交叉验证过三条：
>
> 1. **抽掉 `<script>` 标签**（内容全在预渲染 HTML 里，不注水也能读）：Performance 99，FCP 915ms，LCP 2113ms。
>    LCP 仍然 2.1s，而这时页面已经不含任何 JS——剩下的就是节流本身。
> 2. **CSS 内联进 HTML**：LCP 2951ms，比外链的 2865ms 还差一点（HTML 从 86 KB 涨到 160 KB）。
> 3. **关掉全站 CSS 动画 / 删掉 grain 噪点层 / 删掉 hero 立绘 / 首屏文案改系统字**：LCP 全部落在 2.86–2.91s，动都不动。
>
> 结论：**不为了这个数字动设计**。LCP 元素是 `.hero-sub` 那句副标题，它在预渲染 HTML 的首屏位置，
> 浏览器 332ms 就画出来了。真实网络下的 CWV 要等上线后看 CrUX，本地模拟节流量不出来。
>
> 记下来的三条不做的优化：**代码分割**（`renderToString` 撑不住 `React.lazy`，而预渲染是「刷新可用 + 无 JS 可读」的前提）、
> **`font-display: optional`**（首屏中文会闪一下系统字，LCP 只改 5ms）、**图片预载**（首屏没有图片进 LCP）。

> M7 记录二：**四条真做了的优化，Performance 88 → 95。**
>
> | 优化 | 依据 | 效果 |
> |---|---|---|
> | 首屏字体 `<link rel=preload>` | 字体在关键请求链第三层（HTML → CSS → `@font-face` 解析 → woff2），120ms 才发出 | FCP 2859 → 1960ms，Performance 88 → 92 |
> | 注水脚本 `fetchpriority="low"` | `type=module` 默认 High，149 KB 的包把字体挤到后面 | FCP 1960 → 911ms，而 TTI 2918 → 2919ms（一毫秒没退） |
> | 首屏之下的分区 `content-visibility: auto` | 首页 HTML 有 1230 个节点 / 481 条 SVG 路径，LCP 的 85% 是 Render Delay | 移动端 FCP 620 → 308ms（页内实测） |
> | 五张卡的立绘 `content-visibility: auto` | 主线程 styleLayout 2041ms + paint 1330ms | styleLayout → 617ms，paint → 580ms，展开卡片 INP p50 232 → 136ms |
>
> 预载分两批：首页六份（ui 的 400/700、latin 的 400/700、Chakra Petch 500/600），
> `/docs` 那几页额外三份（docs 的 400/700 + JetBrains Mono）。无差别预载会让首页凭空多下 92 KB，
> 把 7.2 按作用域切片省下来的量原封不动还回去。
> `noto-sans-sc-wordmark-900` 不预载：1.2 KB 低于 `assetsInlineLimit`，Vite 已经内联成 data URI 了。
>
> 两条 `content-visibility` 都验过版面无变化：立绘那条逐张滚到视口正中量 `cardH` / `svgH` / 溢出量，
> 桌面与移动五张卡开关前后完全一致；冻结动画后逐块截图比像素，最大差 0.05%（halo 自转的相位差）。
> `contain-intrinsic-size` 都写 `auto`，让浏览器记住上次真实高度，只有第一次滚过去用估值。

> M7 记录三：**INP 用真实交互实测，不用 Lighthouse 的代理指标。**
>
> Lighthouse 是冷启动跑分，没有交互，`INP` 那一格永远空着，只有 `maxPotentialFID` 这个代理值。
> 直接挂 `PerformanceObserver({ type: 'event', durationThreshold: 0 })`，在 CPU×4 下走完
> 五张方向卡各开各收 + 三个展台各开各收 + 弹幕四步，取 `click` 事件时长：
>
> | CPU 节流 | n | p50 | p75 | p95 | max |
> |---|---|---|---|---|---|
> | ×1 | 32 | 48ms | 48ms | 48ms | 48ms |
> | ×2 | 32 | 56ms | 96ms | 128ms | 128ms |
> | ×4 | 32 | **136ms** | 216ms | 264ms | 264ms |
>
> p50 过线，p75 起超。拆开看：**慢的全是「展开」，收起只有一半**（卡1开 256ms / 卡1收 128ms），
> 且 216ms 里输入延迟占 82ms、处理占 51ms、呈现占 85ms——处理逻辑本身不慢，慢在那一帧的样式与绘制。
>
> 试过四条都没用：拆掉 motion 的 `layout` / `layoutId`（264ms，没变）、`contain: layout paint` 加在
> `.track-tilt` 或 `.track-portrait` 上（168–224ms，没变）、停掉立绘的 halo 与 prop 动画（216ms，没变）、
> 停掉全站 CSS 动画（224ms，没变）。有用的只有那条 `content-visibility`（232 → 136ms）。
> `reducedMotion: reduce` 下 p50 40ms / max 128ms，全程达标。
>
> **CPU×4 是 Lighthouse 模拟中端手机的节流倍率，不是真机。** 真实设备落在 ×1 到 ×4 之间，
> ×2 的 p75 96ms 距上限还有一倍余量。留在这里当基线，上线后看 CrUX 的真实分布再决定要不要继续压。

> M7 记录一：**不出 `og:image`，`twitter:card` 取 `summary` 而不是 `summary_large_image`。**
>
> 本站没有 1200×630 的社交配图。没有配图时有三条路：不出 `og:image`（抓取端退化为纯文本卡片）、
> 指向 `favicon.svg`（多数抓取端不接 SVG，接了也是一张 1:1 小图当主视觉）、
> 或者拿一张展台截图凑（那些图是项目界面，跟站点主题对不上，且都不是 1200×630）。
> 取第一条。`summary_large_image` 明确要求 ≥300×157 的图，没图就声明它等于自己给自己挖坑。
> 要做大图卡先做配图，那是设计工作，不是构建脚本能变出来的。

> M7 记录二：**`sitemap.xml` 不写 `changefreq` 与 `priority`。**
>
> Google 早就公开说这两个字段一律忽略。填了只是给自己多一份要维护的假数据——
> 站点改版后没人会回来把 `changefreq: weekly` 改成 `monthly`。只留 `loc` 与 `lastmod`。

> M7 记录三：**验预渲染产物必须用「像 GitHub Pages 那样的静态服务器」，不能用 `vite preview`。**
>
> `vite preview` 有 SPA fallback：`/docs/nope/` 也会返回 200 加首页 HTML，
> 于是「这条路由真的出了静态页」和「被 fallback 兜住了」两种情况在它上面长得一模一样。
> 写一个 40 行的 `node http.createServer`：目录取 `index.html`，无尾斜杠的目录发 301，
> 找不到就 404 不回退。另外要对文本资源开 gzip 并给出 `cache-control`，否则 Lighthouse
> 量到的是 469 KB 原始 JS 而不是 153.7 KB 的实际传输量，模拟节流下 FCP 直接虚高两秒。
>
> 实测：`/` 200、`/docs` 301 → `/docs/` 200、`/docs/git-flow/` 200、`/sitemap.xml` 200、
> `/robots.txt` 200、`/.nojekyll` 200、`/docs/nope/` **404**。最后那条才是这套验法的意义。

> M5 修正记录：**`/docs/:id` 在构建期出静态页，SSG 预渲染从 M7 提前一部分到 M5。**
>
> 冲突点：GitHub Pages 是纯静态托管，没有 SPA fallback。用户直接访问
> `https://yfy-club.github.io/docs/git-flow` 或在那个页面按 F5，服务器找不到 `docs/git-flow/index.html` 就返回 404。
> 而第 6 节要求「无 JS 时输出静态 HTML 骨架，内容可读」，第 10 节又把 SSG 排在 M7——M5 要能刷新，M7 才做预渲染，两条撞上。
>
> 比过三条路：
>
> | | 刷新 | 无 JS | SEO | 代价 |
> |---|---|---|---|---|
> | A 构建期出静态页 | 可用 | 可读 | 完整 | 现在就要搭预渲染管线 |
> | B `404.html` 重定向 | 闪一下 | 白屏 | 拿不到 | 低 |
> | C hash 路由 | 必对 | 白屏 | 拿不到 | 零，但 URL 不是 4.4 写的 `/docs/:id` |
>
> 取 A。M7 反正要做 SSG，M5 顺手把「无 JS 可读」一起拿下，M7 不必再改一遍路由层。
>
> 落地：`vite build` 之后跑 `scripts/prerender.ts`，用 `react-router` 的 `StaticRouter` 把每条路由
> `renderToString` 进 `dist/index.html` 模板，产出 10 个页面（`/`、`/docs`、8 篇）。
> 客户端 `main.tsx` 见到 `#root` 已有内容就走 `hydrateRoot`，否则 `createRoot`。
> M7 接手时只需补 head 的逐页 `title` / `meta` 与 sitemap，管线不动。
